Where IMI Fits (and Where It Doesn't)

Use JPEG XL / AVIF / zenjpeg for

Final Web Publishing & Minimum Bandwidth

JPEG XL and AVIF achieve ~10–25% smaller files than IMI at matched perceptual quality and on lossless photos. When network transfer size for end-user web delivery is the primary bottleneck, JPEG XL, AVIF, and zenjpeg are the right tools.

Use IMI (.imi / .imijset) for

Intermediate Pipelines, Science & Interactive ROI

IMI supports internal processing pipelines, scientific/detector arrays (photon counts, DEMs, CCD frames), multi-gigapixel tile servers and browser WASM applications. The retained performance measurements remain tied to their recorded builds; V4 correctness qualification is separate from a throughput measurement.

Upgrade and validate files

Ordinary writers emit IMI v4; explicit compatibility readers retain v2/v3. The upgrade APIs rewrite encoded framing without re-encoding pixels. Strict validation then fully decodes every recognized image and verifies all declared checksums.

imij-wasm validate image.imi new-scratch-file
imij-wasm validate --help

Unreferenced stills and pages need no raster scratch. Referenced images and animation composition use caller-owned disk scratch. Unknown ancillary extensions remain opaque. Validation, limits and CLI help →
