Architectural Trade-offs · Measured Performance

Why IMI exists: trading 15% compression density for multi-gigabyte/s parallel decode and O(1) region access.

IMI is not a replacement for JPEG XL, AVIF, or JPEG in bandwidth-constrained web publishing. JPEG XL achieves better compression density on photographs and supports f32, HDR, and parallel decoding; zenjpeg with restart markers and parallel PNG extensions also scale across cores. IMI is designed for the regime where peak multi-threaded decode throughput, scientific/intermediate data fidelity (all 11 sample types from u8 through f64, 7 channel layouts including CMYK and Oklab), bounded 41 MB RSS gigapixel encoding, and 2-RTT HTTP byte-range random access are the primary constraints.

1. Peak Multi-Threaded Decode Throughput (Ryzen 9 7900X, Zen 4)

Every IMI coding mode—from Quick packet/bit-smart units to SplitHuf/RunLevel lossy DCT and 16-lane interleaved rANS lossless stripes—decomposes the image into independent row stripes and optional column groups. Within each lossless or lossy unit, 16 independent rANS state lanes decode in lockstep SIMD without cross-lane data dependencies:

2. Scientific & Intermediate Data Workflows (32 Public Arrays, 7 Classes)

In scientific and intermediate workflows (astronomy CCD frames, digital elevation models, synchrotron photon-count detectors, microscopy, remote sensing), data is rarely 8-bit sRGB. 3. Self-identifying V4 groups and retained V3 unit ordinals

V4 group IDs are baseline syntax. Its front/tail directory names spatial tiles and immutable model dependencies; one tile range can supply several decode workers. The feature-26 unit-ordinal layout and request-count observations below describe retained V3 files.

When serving a single large .imi file over HTTP byte ranges using an untrusted trailing unit table (uTAB), Feature 26 (unit_ordinals, Head Record 37) prefixes each main unit record with its 0-based LEB128 varint ordinal. Region readers verify fetched spans locally in 2 HTTP requests (405 ms at 12.5 MB/s) instead of scanning all 352 record headers across the file (7,446 ms), at a cost of just +595 bytes (+0.020%) on a 3.01 MB file.

4. Candid Format Self-Critique: What Excels vs. Which Compression Methods Are "So-So"

Every format feature in IMI is evaluated against measured speed and compression studies across photographic, graphic, and scientific corpora. Here is an honest assessment of which techniques pay for themselves and which are currently "so-so":

Mechanism / Subsystem Verdict Measured Evidence & Architectural Critique
16-Lane Interleaved rANS + Independent Stripes/Groups (SPEC §2.5) ★ Core Strength Delivers 1.1–3.3 GB/s 8-thread native decode and 339–390 MP/s in 16-worker browser WASM without serial bitstream bottlenecks.
16-Bit Sparse Value-Table Maps (SPEC §2.1 Map 9) ★ Strong on u16/u32/f32; Mixed on x86 f16 Smallest lossless coding on EIGER u32 photon counts (0.636 bps, 41% smaller than HDF5 bitshuffle+Zstd), SDSS u16 astro CCDs (4.975 bps), and SI-HDR f16 (−29% size, 0.94× EXR PIZ). Decode speed is 1.04–1.22× faster on f32 and 1.06–1.19× on Apple M4 Pro, but 0.79–0.92× slower on x86 f16 gather/lookup paths (value_tables = false keeps regular maps).
Template Palettes & Bilevel Contexts (SPEC §2.6) ★ Great on Dither/1-Bit; Needs Speed Gate on Screenshots Cuts dithered/indexed graphic size by 2.90× (0.51–0.60× bytes) and speeds up 1-bit decode (1.27× Zen 4). However, because stripe selection currently compares bytes only without a decode-cost penalty, multi-color template stripes (k = 3..5) also win on 23/24 screenshots for ~1% byte savings at a ~7% 1-thread decode slowdown (0.925× aggregate).
Retained V3 Unit Ordinals + Morton Pyramid Sets (Feature 26, imij-set) ★ Core Strength Eliminates the 352-request cold ROI header verification storm (down to 2 requests, 18.4× faster) for +0.020% file size.
Lossy DCT AC Coefficient Coding vs. JPEG XL VarDCT So-So (~10–18% larger than JXL) Trellis quantization gains −3.8% to −4.6% size in both RunLevel and SplitHuf, and adaptive 8×8/4×4 blocks help sharp edges, but IMI's AC coefficient coder stays ~10–18% larger than JPEG XL at matched SSIMULACRA2 / CVVDP on 512px+ photos because it avoids JXL's heavier 2D cross-coefficient context modeling to keep SIMD decode fast.
Lossy Adaptive Quantization (HEAD_AQ) Map So-So (Currently Off by Default) The wire syntax supports per-block AQ maps (HEAD_AQ), but across our paired SSIMULACRA2 + CVVDP studies with and without trellis quantization, no tested AQ heuristic improved both metrics simultaneously. Default aq_gamma is therefore 0 until a multi-metric masking model is tuned.
Quick Packets on 8-Bit Natural Photographs (SPEC §2.13) Great on UI / 16b Shifts; So-So on 8b Photos Quick mode excels on UI screenshots (1.69 bpp, 1.46 GP/s), pixel art (0.29 bpp), and shifted/replicated 16-bit sensors (--quick-bits saves 2.0×). On noisy 8-bit natural photos, however, Quick gets 10.72 bpp (2.24:1) at 163 MP/s (1T), whereas IMI Lossless Effort 0 (16-lane rANS) achieves 6.07 bpp (1.77× smaller) and decodes faster at 270 MP/s (1T) / 1,121 MP/s (8T).
Smooth 32-Bit IEEE Float Grids (ERA5 CF Fields) Good on DEMs; So-So on Smooth CF Floats IMI beats HTJ2K and JPEG-LS on f32 terrain DEMs (12.41 bps, 10 GB/s 8T decode), but on smooth ERA5 climate f32 fields (10.91 bps) it is ~19% larger than TIFF Deflate with horizontal byte-shuffle (8.79 bps), because byte-shuffling IEEE754 exponent bytes across a row compresses smooth float gradients tighter than whole-sample residual prediction.
