Validate every image, including its pixels

Strict validation supports V4 and retained formats. It succeeds only after fully decoding the primary image, frames/pages, previews, gain maps and unique plane tiles. Every declared file, pixel and temporal-reference checksum must match. There is no structure-only mode.

Command line

imij-wasm validate image.imi new-scratch-file
imij-wasm validate image.imi new-scratch-file --max-scratch-bytes 1073741824
imij-wasm validate --help

# From the source checkout:
just validate-v3 image.imi new-scratch-file

Input uses positional reads from a file, not stdin buffering. The scratch path must be new. It is never overwritten or automatically removed; failure can leave partial scratch. Success prints JSON counters; failure exits with status 2.

Large images and references

Decoded rows feed incremental XXH3 checksum verification. Only images actually referenced later are retained. Independent stills/pages, previews, gain maps and plane tiles need no raster scratch. Animation composition may also need disk scratch. Retained references remain until validation finishes.

Use --max-file-bytes, --max-decoded-pixels, --max-scratch-bytes and --max-working-bytes to set admission limits. A limit failure is an error, never partial success. Planned storage limits are not a process-RSS guarantee; encoded plane tiles have their own bounded buffers.

What the result means

Known framing, indexes, plane descriptors and interpreted metadata are checked. Unknown checksum algorithms and unsupported image coding fail. Unknown ancillary extensions and ordinary attachments retain their opaque semantics. Missing checksums stay absent, and the report counts which checksums were verified.

A region read or browser preview validates only what it uses, not the whole file. The strict validator is currently a Rust/std and file-based CLI operation.

Upgrade first when needed

imij::upgrade_image migrates v2/v3 image framing to v3. imij_set::upgrade also migrates images in archives. Both reject the retired native-JPEG/component experiment; it is not legal v3 data. These operations preserve encoded pixel payloads but do not establish pixel correctness. Image rewriting currently buffers one encoded entry under an explicit size limit; it never allocates the decoded raster. Run strict validation on each upgraded image.
