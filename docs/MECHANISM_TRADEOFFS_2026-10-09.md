## 1. Lossy entropy grammars and seeds

Which tier uses which: Compact = run-level. Balanced picks split-Huffman when the fitted cost model
predicts time ratio <= 0.85, Fast/Fastest at <= 0.93. Images up to 64K px are coded both ways and keep
split-Huffman if it is smaller (docs/LOSSY.md:1047-1051). Packed and Split are never chosen by any tier
(docs/SIMPLIFICATION.md:20-21). Trellis (effort 9/10) runs only on XYB run-level (CHANGELOG.md:80).
Compact restart states apply only to RunLevel and Packed (docs/SUBBLOCKS_AND_COMPACT_STREAMS.md:125,138-139).

## Ten removals: most test simplification for the least measured loss

1. **Packed entropy (id 1).** Measured loss: none. It is 6-7% larger and slower on every tier, and no tier picks it. Removing it takes one grammar out of the grammar x tier x seed x route matrix, plus `entropy_pk_avx2.rs` and its compact-state support.
2. **Lab code.** lab.rs, lab_rans, lab_rice, lab_huff, huffman, ans, lanes_lab, rdoq_lab, aq_field_lab, chroma_lab and block_lab total about 5,900 lines on origin/main. The studies are concluded, and RDOQ is superseded by the trellis. Production loss: none.
3. **Subblocks (Dct2/Dct4/Adaptive4) and independent channel sampling.** Every measured policy is 28-134% worse at matched rate, and B−Y half-res is +0.02..0.16%. The kernels are scalar and native decode speed was never measured. It is a whole layout axis in every lossy route (subblock.rs 662).
4. **Split rANS (id 2).** No tier uses it. The only measured loss is its 1.8-3.6% byte edge over SplitHuf, for explicit-API users.
5. **~~imij-gather~~ (done) and the kernel_choice race.** The unsafe crate is retired: magetypes 0.9.30 `gather_wrapping`/`scatter_select` serve the same kernel with identical decoded bytes and within-noise speed (benchmarks/archmage_gather_2026-10-09/). The race stays: gather still buys ~2% on parts of Zen 4 while software lookups win on Zen 5, and it is the only mechanism that adapts. Removing it would still drop the 3.58 MB transient and a pinning variable from every timing test.
6. **AQ channel (DC 4th channel, multipliers).** Off by default, and no encoder rule beat AQ off on CVVDP or SSIM2. The only win is lab BA-max steering. Removing it shrinks the DC-channel matrix (AQ, keep blocks and exact blocks are mutually exclusive variants of that channel).
7. **Fast tier, merged into Balanced.** Fast costs +1.2..2.6% bytes for +2.0..2.8% speed (v3 at SSIM2 80). The tier byte is informational, so this is encoder-only and cuts the tier x stripe-cap x DC-rule matrix by a quarter. Measured loss: <= 3% decode speed.
8. **Lane counts L = 1..15 (fix L = 16).** Value: not measured, and the encoder default is 16. Removing them takes out the 42.30 MB vs 2.98 MB hostile amplification and a whole geometry axis from lossless tests.
9. **Lossless AVX-512 row kernels, if AVX2 kernels run on v4.** Measured loss on Zen 4: suite +1.6% (and AVX2 is faster on gray2048); Zen 5 not measured. Keep the VBMI writer (+5-8%). This deletes one of two hand-written lossless kernel families (1-, 2- and 3-row each).
10. **Inter predictors 8 and 9.** Value never measured separately from 7. Removing them takes two recon branches off every tier. It needs one A5 run with predictor 7 only before deciding; that run costs minutes.

Runners-up with no measured value but more product risk: `mCMP` (savings never measured), Paeth and avg(W,NE) predictors plus decorrelation mode 3 (never chosen in nested DC; standalone use not traced), compact rANS restart states (their -10.8% at q5 was measured before tall stripes; re-measure).

## Five that must stay (largest measured value)

1. **The AVX2/NEON SIMD entropy and reconstruction tiers.** Lossless runs about 6x scalar (283 vs 48 Mpx/s); lossy run-level about 2.5x (322 vs 129). wasm128 gives 1.6x on lossless.
2. **Automatic lossy stripe heights and nested DC stripes, with the shared DC decode.** 3-30% smaller at q5 vs one-row stripes, and 18.5% at 1024² q5 for 64 vs 8 px. The shared DC schedule is 1.5-5.8x faster at all threads.
3. **Seed bank 1.** -12.8% at 64 px, -6.2% at 128 and -2.6% at 256, with no file larger. Decode cost is a few µs.
4. **Inter frames (lossless and lossy keep blocks).** -74..-97% on mostly-static animations (synthetic) and 6-8% on thin-slice stacks. Decode is 3-25x more frames/s.
5. **Split-Huffman, the speed grammar.** +11..43% 1T decode for +4..11% bytes. It is the reason the Fast and Fastest tiers exist, and the best scalar fallback (293-400 Mpx/s).

Close behind are content-specific wins:
- palette stripes: plots -15%, decode up to 2.25x
- exact blocks: scans and plots -10..12% in Compact
- column groups: 1.2-3x on images wider than 8K
- AVX-512 two-stripe pair kernel: +5..12% at 1T
- trellis: -3.1..-4.6% at effort 9-10, encoder only
- near-lossless (PR #8): 13-93% on science data
