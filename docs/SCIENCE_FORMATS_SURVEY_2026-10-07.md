# Scientific imaging formats: what the leaders do (survey)

2026-10-07. Desk review plus one small measurement. IMIJ was read at git `5f08b52` (2026-10-06) with
the working tree as found; nothing in the repo was changed. Each claim about an external format links
the spec or doc I read. Where a source was not read in full, the text says so. 

Note added on commit: IMIJ was read at `5f08b52`. Since then main gained versioned profiles (SPEC
section 0: Lossless, Extended, Lossy, Compact) and the `cSUM` checksum is in review as PR #2. The gap
analysis and recommendations are in [SCIENCE_GAPS_2026-10-07.md](SCIENCE_GAPS_2026-10-07.md).

Severity scale used in section 4: **Blocker** (the community cannot adopt IMIJ for this data without
it), **High** (adoption needs a sidecar or a lossy workaround), **Medium** (a workaround exists but
costs size, memory or interop), **Low** (nice to have).

## 1. What each scientific community needs

| Domain | Dominant formats | Sample types in practice | Shape and channels | Compression practice | Metadata that must survive |
|---|---|---|---|---|---|
| Astronomy | FITS ([4.0 standard](https://fits.gsfc.nasa.gov/standard40/fits_standard40aa-le.pdf)) | BITPIX 8, 16, 32, 64 (two's complement), −32 and −64 (IEEE single and double) (Table 8). Unsigned 16/32/64 are stored signed with BZERO = 2^15/2^31/2^63 (Table 11) | Up to 999 axes (NAXIS); spectral cubes, time series | [Tiled image compression](https://fits.gsfc.nasa.gov/registry/tilecompression.html) (now §10 of FITS 4.0): RICE_1, GZIP_1/2, PLIO_1, HCOMPRESS_1 per tile, plus float quantization with subtractive dither (§2 below) | `physical = BZERO + BSCALE × array` (Eq. 3), BUNIT, BLANK for integer nulls and NaN for floats, WCS (§8: CTYPEi, CRPIXj, PCi_j, CDELTi), time (§9), [CHECKSUM/DATASUM](https://fits.gsfc.nasa.gov/registry/checksum.html) |
| Microscopy / bioimaging | [OME-TIFF](https://ome-model.readthedocs.io/en/stable/ome-tiff/specification.html), [OME-Zarr (NGFF 0.5)](https://ngff.openmicroscopy.org/0.5/) | OME [PixelType](https://www.openmicroscopy.org/Schemas/Documentation/Generated/OME-2016-06/ome_xsd.html): int8/16/32, uint8/16/32, float, double, complex, double-complex, bit | NGFF: 2 to 5 axes, "2 or 3 entries of type:space", optional time and channel, order t, c, z, y, x. OME-TIFF maps planes to IFDs by DimensionOrder | OME-Zarr 0.5 builds on Zarr v3 (`zarr_format: 3`), so it can use v3 codecs and sharding. OME-TIFF stores SubIFD pyramids (added in OME 6.0.0) | Per-axis `unit` (UDUNITS-2 names) and per-level `scale` and `translation` transforms, levels ordered from highest to lowest resolution, channel `color`/`window`/`label` (`omero` block), integer-typed `labels` images, physical size, wavelengths, fluorophore |
| Remote sensing / geospatial | GeoTIFF ([OGC 19-008r4](https://docs.ogc.org/is/19-008r4/19-008r4.html)), COG ([OGC 21-026](https://docs.ogc.org/is/21-026/21-026.html)), GDAL ([GTiff driver](https://gdal.org/en/stable/drivers/raster/gtiff.html)), NetCDF/HDF5, Zarr | GDAL GTiff: Byte, (U)Int16, (U)Int32, Float32, Float64, CInt16, CInt32, CFloat32, CFloat64 | Many bands; hyperspectral needs hundreds | COG: tiled only, overviews, header ahead of data for HTTP range reads. GDAL offers DEFLATE/ZSTD/LZW with PREDICTOR 2/3, plus [LERC](https://github.com/Esri/lerc) with MAX_Z_ERROR, JXL, WEBP, NBITS, DISCARD_LSB. [CCSDS 123.0-B-2](https://ddd.uab.cat/pub/artpub/2019/213186/remsen_a2019v11n11p1390.pdf) for on-board hyperspectral coding | CRS through GeoKeys (EPSG codes), raster-to-model transform (ModelPixelScale/Tiepoint/Transformation), PixelIsArea vs PixelIsPoint, nodata (GDAL_NODATA tag 42113, one value for all bands), per-band scale/offset/units (GDAL_METADATA tag 42112) |
| Medical | DICOM ([PS3.5 §8](https://dicom.nema.org/medical/dicom/current/output/chtml/part05/chapter_8.html)) | 8/12/16-bit stored in 8 or 16 allocated bits, signed or unsigned (Pixel Representation 0/1). Float Pixel Data (7FE0,0008) and Double Float Pixel Data (7FE0,0009) allow any IEEE 754 value "including NaN" | Frames, volumes, multi-frame | Transfer syntaxes ([PS3.6 Annex A](https://dicom.nema.org/medical/dicom/current/output/chtml/part06/chapter_A.html)): JPEG-LS lossless and near-lossless (.4.80/.81, Bits Stored 2–16, [§8.2.3](https://dicom.nema.org/medical/dicom/current/output/chtml/part05/sect_8.2.3.html)); JPEG 2000 (.4.90–.93, Bits Stored 1–38, [§8.2.4](https://dicom.nema.org/medical/dicom/current/output/chtml/part05/sect_8.2.4.html)); HTJ2K (.4.201–.203, 1–38 bits, [§8.2.14](https://dicom.nema.org/medical/dicom/current/output/chtml/part05/sect_8.2.14.html)); JPEG XL (.4.110 lossless, .111 JPEG recompression, .112 lossy; lossless Bits Stored 1–24, [§8.2.15](https://dicom.nema.org/medical/dicom/current/output/chtml/part05/sect_8.2.15.html)); RLE; deflated frames ([§8.2.16](https://dicom.nema.org/medical/dicom/current/output/chtml/part05/sect_8.2.16.html)) | [Rescale Slope/Intercept](https://dicom.nema.org/medical/dicom/current/output/chtml/part03/sect_C.11.html) ("Output units = m*SV + b"), Rescale Type (HU, OD, ...), Bits Stored and High Bit, windowing |
| HDR / VFX | OpenEXR ([technical intro](https://openexr.com/en/latest/TechnicalIntroduction.html)) | HALF, FLOAT, UINT (32-bit) per channel | Arbitrary named channels with dotted layers (`light1.specular.R`), deep (variable samples per pixel), multi-part, data window vs display window | Lossless: RLE, ZIPS/ZIP, PIZ, HTJ2K256/HTJ2K32 (v3.4.0, 2025-09), ZSTD (v3.5.0, 2026-09). Lossy: PXR24 (float to 24 bits), B44/B44A (half), DWAA/DWAB, LJ2K (v3.5.0) ([news](https://openexr.com/en/latest/news.html)). Tiles with mip and rip levels | Typed header attributes (chromaticities, colorInteropID, worldToCamera, ...) |
| Synchrotron, EM, crystallography | HDF5/NeXus, [MRC2014](https://www.ccpem.ac.uk/mrc_format/mrc2014.php) | Detector frames are integer counts. MRC modes: 0 int8, 1 int16, 2 float32, 3 complex int16, 4 complex float32, 6 uint16, 12 float16, 101 packed 4-bit | Stacks of frames, 3-D maps with Å voxel size | EIGER detectors write [bitshuffle + LZ4 ("bslz4")](https://lists.nexusformat.org/pipermail/nexus/2016/000903.html) HDF5 chunks; [bitshuffle](https://github.com/kiyo-masui/bitshuffle) is HDF5 filter 32008. [Registered HDF5 filters](https://github.com/HDFGroup/hdf5_plugins/blob/master/docs/RegisteredFilterPlugins.md) include Blosc 32001, Blosc2 32026, Zstd 32015, ZFP 32013, SZ3 32024, JPEG-LS 32012, JPEG 2000 32031 | Cell dimensions in Å, axis mapping, extended headers (MRC); NeXus groups (HDF5) |
| Climate / weather | netCDF-4/HDF5 with [CF 1.12](https://cfconventions.org/Data/cf-conventions/cf-conventions-1.12/cf-conventions.html), Zarr | float32/float64 | 3-D/4-D grids, unlimited time dimension for append ([HDF5 extendible datasets](https://support.hdfgroup.org/documentation/hdf5/latest/_h5_d__u_g.html)) | Lossless deflate/zstd behind quantization: CF §8.4 records BitRound (NSB, 1–23 bits for float), BitGroom, DigitRound and Granular BitRound (NSD). [Klöwer et al. 2021](https://www.nature.com/articles/s43588-021-00156-2): most CAMS variables carry "fewer than 7 bits of real information per value"; with 4-D compression they report "factors beyond 60×" | `units` (UDUNITS, §3.1), `standard_name` (§3.3), `_FillValue`/`valid_range` (§2.5.1), `scale_factor`/`add_offset` packing (§8.1), `grid_mapping` CRS (§5.6) |

What runs through every row: **exact numerics** (signed ints, float64, NaN as missing), **a linear
calibration** from stored values to physical units, **a missing-data convention**, **physical
coordinates** (pixel size, origin, CRS or WCS), **N-D data beyond RGB**, and **lossy coding only with a
stated numerical error bound**. Perceptual quality metrics do not appear in any of these communities'
specs.

## 2. What the best modern formats and codecs do

| Format / codec | What it does that matters to scientists | Source |
|---|---|---|
| **JPEG XL** | 1 or 3 colour channels plus up to 4096 extra channels (4099 components). Extra-channel types: alpha, depth, spot colour, selection mask, black, CFA, thermal, optional, unknown. Each extra channel has its own bits and exponent bits and a `dim_shift` (power-of-two subsampling). Integers up to 31 bits unsigned or 32 bits signed; floats up to binary32, including bfloat16; no float64. Modular mode is integer-only and lossless (RCTs, delta palette, Squeeze). Independently decodable groups with a TOC, for parallel and ROI decode. Level 10 allows 2^40 pixels and 256 extra channels; Level 5 allows 4. I found no normative max-error (near-lossless) mode in the sources I read | [arXiv 2506.05987](https://arxiv.org/abs/2506.05987) §2.3, §2.4, §4.1; [libjxl codestream_header.h](https://github.com/libjxl/libjxl/blob/main/lib/include/jxl/codestream_header.h); [format overview](https://github.com/libjxl/libjxl/blob/main/doc/format_overview.md) |
| **JPEG 2000 / HTJ2K** | Reversible 5/3 and irreversible 9/7 wavelets give resolution scalability. Precincts and code-blocks give spatial random access; Maxshift gives ROI. DICOM allows Bits Stored 1–38, signed or unsigned. HTJ2K "speeds-up JPEG 2000 by an order of magnitude" at "slightly reduced coding efficiency", with "reduced quality scalability" and lossless transcoding to and from Part 1 | [jpeg.org HTJ2K](https://jpeg.org/jpeg2000/htj2k.html); DICOM [§8.2.4](https://dicom.nema.org/medical/dicom/current/output/chtml/part05/sect_8.2.4.html), [§8.2.14](https://dicom.nema.org/medical/dicom/current/output/chtml/part05/sect_8.2.14.html); IMIJ's own [EVAL_JPEG2000_FEATURES_2026-10-04](EVAL_JPEG2000_FEATURES_2026-10-04.md) |
| **JPEG-LS** | LOCO-I: MED predictor, context modelling, Golomb codes. **Near-lossless**: "every sample value in a reconstructed image component is guaranteed to differ from the corresponding value in the original image by up to a preset (small) amount" δ (NEAR). This is achieved by quantizing the prediction residual inside the DPCM loop with bins of size 2δ+1; lossless is the special case δ = 0. DICOM: 2–16 bits | [Weinberger, Seroussi, Sapiro, IEEE TIP 2000](https://www.sfu.ca/~jiel/courses/861/ref/LOCOI.pdf) §IV; [ITU-T T.87](https://www.itu.int/rec/T-REC-T.87-199806-I/en) (overview page only) |
| **CCSDS 123.0-B-2** | Lossless and near-lossless coding of multispectral and hyperspectral images with **user-defined absolute and/or relative error limits**, per band, optionally updated periodically. Uses closed-loop quantization of prediction errors, prediction from neighbouring bands, and a hybrid entropy coder for low-entropy residuals | [Blanes, Kiely, Hernández-Cabronero, Remote Sensing 2019](https://ddd.uab.cat/pub/artpub/2019/213186/remsen_a2019v11n11p1390.pdf); [CCSDS magazine overview](https://ddd.uab.cat/pub/artpub/2021/299983/ccsds_magazine_123x0b2.pdf) (not read) |
| **Zarr v3** | Types: bool, int8–uint64, float16/32/64, complex64/128 and raw `r<bits>`. Required `fill_value`. Regular chunk grid with chunk-key encoding. Codec pipeline: array→array\*, exactly one array→bytes, bytes→bytes\*. Optional `dimension_names`. Extensions carry `must_understand`. **Sharding**: many inner chunks per stored object, with an index of (offset, nbytes) uint64 pairs at the start or end; 2^64−1 marks an empty chunk; the index may be protected by crc32c, so a reader fetches the index and then byte ranges. **crc32c** codec appends a 4-byte LE checksum | [core](https://zarr-specs.readthedocs.io/en/latest/v3/core/index.html), [sharding](https://zarr-specs.readthedocs.io/en/latest/v3/codecs/sharding-indexed/index.html), [crc32c](https://zarr-specs.readthedocs.io/en/latest/v3/codecs/crc32c/index.html) |
| **Blosc2 / bitshuffle** | Filters (shuffle, bitshuffle, delta, trunc_prec, bytedelta) feed fast codecs (BloscLZ, LZ4, Zstd, zlib, plugins such as ZFP and grok JPEG 2000). B2ND N-D arrays use two-level chunk and block partitioning. Bitshuffle transposes bits within blocks and compresses each block while it is in L1; the README states "roughly 1 byte per clock cycle", up to 2 on Haswell and later | [C-Blosc2](https://www.blosc.org/c-blosc2/c-blosc2.html), [bitshuffle](https://github.com/kiyo-masui/bitshuffle) |
| **SZ3** | Prediction-based, error-bounded lossy compression of float/double/int32/int64 arrays in 1–4-D. Modes ABS, REL (value-range relative), PSNR, NORM, ABS_AND_REL, ABS_OR_REL. The README says it "guarantees that every decompressed value differs from the original by no more than the error bound you set". HDF5 filter 32024 | [SZ3 README](https://github.com/szcompressor/SZ3) |
| **ZFP** | 4^d blocks (1–4-D). Fixed-rate mode allows random access to blocks; fixed-precision; fixed-accuracy `|f−g| ≤ 2^minexp`, which the docs say "is not always tight (especially for 3D and 4D arrays)" but can be set conservatively; reversible mode is bit-exact lossless | [ZFP modes](https://zfp.readthedocs.io/en/latest/modes.html) |
| **MGARD** | Multigrid error control in L∞, L2 and Sobolev s-norms, preservation of quantities of interest, ROI support (BlockMGARD), GPU (MGARD-X) | [MGARD](https://github.com/CODARcode/MGARD) |
| **FITS float quantization** | Per tile, `I = ROUND((F − ZZERO)/ZSCALE + R − 0.5)` (Eq. 2) with a reproducible random sequence seeded by ZDITHER0, and the inverse `F = (I − R + 0.5)·ZSCALE + ZZERO`. ZSCALE is chosen as a fraction 1/Q of the background RMS noise, which keeps about log2(Q)+1.792 bits of noise (Q = 8 keeps about 4.8 bits). SUBTRACTIVE_DITHER_2 keeps exact 0.0. NaN goes to ZBLANK. A tile that cannot be quantized falls back to GZIP. Lossy codecs need a separate NULL_PIXEL_MASK. HCOMPRESS: scale 0 or 1 is lossless; scale = 2σ gives about 1.5 bits/pixel with an RMS error of about σ/2 (the convention's rule of thumb) | [Tiled image compression v2.3](http://fits.gsfc.nasa.gov/registry/tilecompression/tilecompression2.3.pdf) §4, §5, §6.4 |
| **TIFF predictors** | Predictor 2: horizontal differencing (GDAL: 8/16/32/64-bit). Predictor 3: reorder float bytes into planes of sign+exponent, high mantissa and low mantissa, then byte differencing, so Deflate/LZW see slowly changing bytes. GDAL supports it for 16-, 32- and 64-bit floats | [Adobe TIFF TN3](http://chriscox.org/TIFFTN3d1.pdf); [GDAL GTiff](https://gdal.org/en/stable/drivers/raster/gtiff.html) |
| **LERC** | User-set per-pixel **MaxZError** (0 = lossless for integers). Types char through double. Valid-pixel byte mask, and since v4.0 one nodata value per band. Layout [nBands, nRows, nCols, nDepth]. README timing: encode about 20–30 ms and decode about 5 ms per megapixel per band | [Esri LERC](https://github.com/Esri/lerc) |
| **netCDF quantize / CF §8.4** | BitRound keeps NSB explicit mantissa bits and zeroes the rest, so the lossless stage that follows compresses better. The parameters are recorded in a CF quantization variable | [CF 1.12 §8.4](https://cfconventions.org/Data/cf-conventions/cf-conventions-1.12/cf-conventions.html) |
| **OpenEXR** | Arbitrary named typed channels, deep data, multi-part, tiles with mip and rip levels, data and display windows, typed attributes, and several lossless and lossy codecs (§1) | [technical intro](https://openexr.com/en/latest/TechnicalIntroduction.html) |

## 3. Cross-cutting features: how the leaders do them

| Feature | FITS | OME-Zarr / Zarr v3 | GeoTIFF / COG / GDAL | HDF5 / netCDF-CF | DICOM | OpenEXR | JPEG XL |
|---|---|---|---|---|---|---|---|
| Ints | 8u, 16/32/64 signed; unsigned through BZERO | int8–uint64 | (U)Int8–64 (GDAL) | all widths | 1–16 bits stored (38 with J2K), signed flag | UINT32 | ≤31u, 32s |
| Floats | f32, f64 | f16/32/64 | f32, f64 | f32, f64 | OF, OD | half, float | ≤ binary32 |
| Complex | binary tables only | complex64/128 | CInt16/32, CFloat32/64 | compound types | no | no | no |
| Channels / N-D | 999 axes | 2–5 axes (NGFF), any number (Zarr) | bands | N-D | frames | named channels | 3 + 4096 extra |
| Tiling and ROI | ZTILEn tiles | chunks and shards | tiles (COG required) | chunks | per frame | tiles or scanline blocks | groups and TOC |
| Pyramids | none native | multiscales | overviews | user-defined | separate instances | mip and rip | progressive / LF frames |
| Error-bounded lossy | quantization relative to noise (Q) | via codecs (ZFP, SZ3 in numcodecs and HDF5) | LERC MAX_Z_ERROR | SZ3, ZFP, scale-offset, BitRound | JPEG-LS NEAR | PXR24 (fixed truncation) | none found |
| Missing data | BLANK, NaN, ZBLANK | `fill_value` | GDAL_NODATA, masks | `_FillValue`, `valid_range` | n/a | n/a | n/a |
| Calibration | BSCALE/BZERO, BUNIT | `scale`/`translation` transforms, UDUNITS units | scale/offset/units in GDAL_METADATA | `scale_factor`/`add_offset`, `units` | Rescale Slope/Intercept/Type | attributes | none |
| Coordinates | WCS | axes + transforms | GeoKeys, EPSG | `grid_mapping` | patient/frame of reference | windows, matrices | origin of cropped layers |
| Metadata carrier | 80-char cards | JSON (`zarr.json`) | TIFF tags, XML | typed attributes | tag dataset | typed attributes | Exif, XMP, JUMBF boxes |
| Integrity | CHECKSUM/DATASUM (32-bit ones'-complement) | crc32c codec | none in core | Fletcher32 filter | none at file level in the sections I read | none in the docs I read | none in the docs I read |
| Append / streaming | append HDUs | resize the array, write new chunks | none | unlimited dimensions | multi-frame | none | animation frames |
| Cloud range reads | tile table | shard index | COG layout, `Accept-Ranges` required | none native (Zarr is the cloud answer) | WADO frames | offset tables | TOC |
