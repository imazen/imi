# Experiment ledger

Experiments run on imij, 2026-10-01 to 2026-10-04: the question, the
data, the machine, the result, what was decided, and where the evidence
lives. Use it to tell which exclusions are sound and which deserve another
look.

How to read the columns:

* **Data** names a data set from [DATA_AND_TOOLS.md](DATA_AND_TOOLS.md)
  (C114 = the 114-image corpus, B32/B23 = the 32-image bench subset / its
  23 RGB8 images, P15 = 15 photos at 1024 px, S6 = 6 photos at 2048 px,
  M = mosaics, T = tiled images, A5 = the five animation sequences).
* **Machine**: r5900xt (Zen 3, AVX2, shared and often loaded), r7900x
  (Zen 4, AVX-512 as 2x256, idle when timed), dev (Zen 5 9950X3D,
  AVX-512), SDE (Intel emulator, instruction counts and correctness only).
* **Decision**: adopted, rejected, removed (built, then taken out), open
  (measured, no decision), lab (code kept behind `--features lab`).
* **Validity**: how far the result can be trusted, and what would have to
  be true for the decision to flip. "Commit-only" means the numbers are in
  a commit message or README, without a committed raw record; re-measure
  before relying on them. "README history" means the README as it stood
  before the 2026-10-03 rewrite: `git show 9e4330c5:README.md`.

Lossy experiments E1-E18 are written up in full in [LOSSY.md](LOSSY.md);
this ledger summarizes them and adds everything after E18.

## 6. Methodology lessons (read before measuring)

2026-10-04 follow-ups are recorded separately to retain their frozen policies and
qualification details: [small blocks and compact envelopes](EVAL_SUBBLOCKS_2026-10-04.md),
[real encoder/decoder Gaborish pair](EVAL_GABORISH_RD_2026-10-04.md),
[optimized seam/Gaborish native kernels](EVAL_RESTORATION_NATIVE_2026-10-04.md),
and [OpenJPH](EVAL_OPENJPH_2026-10-04.md). Small blocks improve some high-quality
endpoints but the initial policies lose low-band RD. The fixed Gaborish pair also
loses RD; neither became a default. Compact envelopes preserve pixels. OpenJPH
illustrates why the same executable and same-host hashes do not establish
cross-SIMD lossy parity: native benchmark outputs were separately scored.

| # | Lesson | How it was found |
|---|---|---|
| M1 | **Never benchmark lossless with an image tiled N times.** When the lane width is a multiple of the tile width, all 16 lanes decode identical data in lockstep and run ~2x faster; groups then look 2x slower. Use `imij-bench mosaic` (different images side by side). | L24: a 1440x900 screenshot tiled 8x decoded at 1002 Mpx/s vs 523 for the original |
| M2 | r5900xt is shared and often at load 25-35: use it for bytes, correctness and instruction counts, not timings. Time on r7900x (idle) with interleaved A/B in one process (`IMIJ_AB_*` switches in decspeed) and repeat runs. | many runs; the old README's 2026-10-01 MB/s table (`decode_zenbench_2026-10-01.txt`) is from the loaded box |
| M3 | Fresh per-decode allocations cost page faults that grow with thread count and image width; separate them from cache effects with `perf stat -e page-faults,system_time` and the keep-scratch lab switch. | W4 |
| M4 | Kernel races decided once per process (AVX-512 gather vs software vs AVX2) can flip between processes; pin with `IMIJ_GATHER=0/1` or `IMIJ_NO_AVX512=1` when comparing. | E12, E18 |
| M5 | Encode at the quality that matches the reference's metric score per image (`parspeed`), not at the same q, when comparing decode speed across codecs. | E7 |
| M6 | Perceptual metrics only (SSIMULACRA2, zensim, butteraugli, cvvdp); PSNR was dropped from imij-bench (ec02171). | E9 |
| M7 | Local CI parity: `just ci-local` runs the same core checks locally before pushing. | CI history |
| M8 | On r7900x (glibc), a multi-threaded decode's speed depends on what the same process decoded before: 64 px stripe files ran up to 2x slower after 8 px files than before them. M4 and N1 showed no such effect. Compare files one per process (with `IMIJ_GATHER` pinned), not several files in one `decspeed` call. | W9 grouped vs per-file runs |
| M9 | **Lab switches must travel with the encode, never in process-global state, when one process encodes several configurations at once.** `imij-cmp ladder-batch` set them per cell in atomics while parallel renditions encoded; in grids mixing a switch's values 6.0% of the AQ + trellis study's cells (4.3-15.1% per run) came out with another cell's value, diluting R2's VALIDATE gain from -4.61% to the published -3.77% (no verdict flipped). Lab builds now carry `LossyConfig::lab`, pinned once per encode; imij-cmp sets no global, and `race_tests.rs` fails if it does. Check a published ladder by re-running it race-free with its own frozen binary (`racefree_run.py`) and comparing encoded sha256 per cell (`compare_rows.py`). | [raceaudit_2026-10-09](../benchmarks/raceaudit_2026-10-09/README.md) |
