## Implemented scope and objective

`zqi/src/lossy/rdoq_lab.rs` contains the search; the main lossy module adds a
lab-only `LossyConfig::rdoq_lambda`, default zero. Supported inputs are U8
RGB/RGBA/Gray/GrayAlpha still images, XYB or YCoCg, explicit RunLevel entropy.
Nonzero λ rejects AQ, decode-speed tiers, LF prediction, inter-frame references
and other sample types. It emits the existing syntax and uses the unchanged
normative inverse. Alpha remains in its existing lossless stream; DC is never
modified. No new feature, dependency or unsafe code was introduced.

This is a **limited zero/tail search**, not general RDOQ. For each block/channel:

1. Preserve the current quantized coefficients as the initial candidate.
2. Evaluate contiguous AC suffix removals at every existing nonzero position,
   including dropping the last nonzero and whole-AC-zero; keep the best tail.
3. Perform one reverse sweep of individual nonzero-to-zero decisions.

There are at most 63 tail trials and 63 single-zero trials per channel. Strict
improvement retains the current candidate on ties. There is no ±1 search,
nonzero insertion, trellis, perceptual neighborhood search, or convergence loop.
The search reduces `D + λ R`, with the provisional objective

```
D = sum_AC ((source_coefficient - q * step) / step)^2
R = sum(-log2(normalized_frequency / M) + actual sign/magnitude raw bits)
```

The FDCT values are canonical normalized coefficients, not AAN-scaled internals.
Dividing squared error by step² weights quantizer bins equally. This is a cheap
quantizer-aware distortion proxy; it is not reconstructed RGB distortion or a
perceptual metric. The λ values are dimensionless exploratory choices, not a
calibrated quality mapping. For a zero trial the distortion delta is computed
as `q * (2 * source/step - q)` in f64.

Initial quantization is unchanged. After the actual stripe/group layout is
formed, its existing histogram/clustering machinery builds provisional tables.
Those normalized frequencies and context maps stay frozen for one search sweep.
An unseen symbol uses a one-slot price (`frequency.max(1)`); that is an explicit
surrogate, not a symbol encodable by the frozen table. The final writer rebuilds
histograms, clustering and tables from the selected coefficients. Every size
reported below includes the complete serialized file: tables, nested DC/alpha,
records, lane states and container. There is no guarantee of fewer final bytes
for every accepted proxy decision. Local prices omit table-header changes,
finite-state rANS renormalization/rounding and record framing.

The rate model follows real RunLevel syntax: EOB, ZRL, joint run/magnitude tokens,
sign and magnitude remainder bits, coefficient-position and remaining-length
contexts. Changing a luma EOB also reprices both chroma channels in that block
and the following lane-local luma EOB. Previous/next blocks respect uneven lane
lengths, row transitions, stripe resets and column-group boundaries. A unit
regression compares affected-rate deltas against the **actual `stripe_tokens`
writer**, including ZRL and raw bits, on 1/7/16/17/33-block-wide, two-row stripes.
This validates the priced token sequence, not exact serialized bit counts.

## FDCT, effort, bounds and threading

Source re-FDCT calls the same `enc_simd::color_rows` and dispatched
`enc_simd::fdct_row` as initial quantization. It reproduces the selected lab FDCT
policy: 0 AAN/FMA, 1 dense, 2 unfused AAN. The process-global policy must remain
fixed during an encode. Debug builds re-quantize each recomputed row and assert
exact equality with the initial coefficients and support masks **before** search.
Integration tests exercise all three modes, both colors, odd edges and groups.
Only mode 0 and the canonical unfused inverse were used for measured quality.
No ISA-wide encoder byte-invariance claim is made.

**Effort remains pixel invariant with this experiment disabled.** When the
separate `rdoq_lambda` opt-in is nonzero, effort affects provisional entropy
tables, and therefore can affect chosen coefficients/pixels. Geometry can also
change decisions through models and lane resets. This dependence is outside the
production effort contract. The matrix includes λ in its pixel-equivalence key;
for active RDOQ it additionally includes effort and geometry. It still checks
encoder-thread invariance. The corpus sweep fixes effort at 10, so it does not
measure an active-RDOQ effort curve.

Extra transform storage is row-sized, not image-sized: `3 * 8 * padded_width`
f32 planes plus `3 * block_width * 64` f32 source coefficients = **1,536 bytes
per block-column per active worker**. At width 1024 without grouping this is
196,608 bytes per worker, plus two fixed 64-i32 candidate arrays (512 bytes) and
loop state. Prices occupy `tables * 128 * 8 + context_count` bytes; default
4 EOB + at most 16 AC tables means about 21 KiB shared prices. Provisional table
construction temporarily uses the existing worker-local histogram storage
(1,155 * 128 * 8 bytes per histogram, about 1.13 MiB), plus clustering scratch.
The provisional tables are dropped after extracting prices. Debug requantization
adds another row-sized q/support buffer. Existing image-wide integer coefficient
storage and task descriptors remain; there is no new image-wide float buffer.
These are source-derived bounds, not measured heap/RSS peaks.

The added work is one extra source color/FDCT pass, one extra table build, and a
bounded scalar search that repeatedly prices up to three 63-AC sequences plus
one next-EOB token. It is intentionally expensive and currently reprices
unaffected tokens rather than using an incremental cache. Units parallelize
using the existing worker scheduler; decisions within a unit are deterministic
in row/block/channel order. 1/4-thread encodes matched exactly in the integration
cases. Decoder syntax, coefficient reconstruction and scratch geometry are
unchanged; fewer surviving AC tokens might reduce work, but that is unmeasured.

## SplitHuf and TCQ assessment

SplitHuf cannot use this price model. Its real cost includes luma group-count
contexts reset at four Huffman section slices, chroma count contexts from luma,
width contexts determined by channel/band/groups-left, each group's shared
`len * max_magnitude_bitwidth` raw magnitude bits, and one sign per nonzero.
A change in a group's maximum can save bits for all three/four positions; a
luma count change can affect chroma widths and the following luma count context.
Section alignment, length varints and rebuilt Huffman tables must then be priced
or compared by complete serialization. Source audit: `huf::stripe_syms`,
`stripe_counts_widths`, `stripe_raw_split`, `encode_huffman_stripes`.
**None of that optimization/pricing has been implemented or measured here.**

The [Motion JPEG RDOQ paper, 2022, section 3](https://www.multimedia.edu.pl/publications/Rate-Distortion-Optimized-Quantization-in-Motion-JPEG.pdf)
supports encoder-side backward AC search with DC excluded; its JPEG/video/PSNR
results do not predict this experiment's perceptual outcome. Zero/tail search
is a narrower candidate family than its unchanged/±1/zero search. Guetzli's
[2017 v1 paper](https://arxiv.org/abs/1703.04421v1) motivates checking local
reconstructions; it does not qualify this coefficient proxy at low rates.

The [released AV2 v1.0.0 coefficient syntax](https://av2.aomedia.org/v1.0.0/index.html#read_coeffs_syntax)
uses an eight-state, parity-driven `Tcq_Next_State[8][2]`; when TCQ is active it
reconstructs nonzero quantizer indices through `2 * quant - q0` and updates the
state at each scanned coefficient. Version provenance is pinned by the
[official specification revision](https://github.com/AOMediaCodec/av2-spec/blob/016ffa9cbb0d5538f92736100f82f78733581149/README.md).
This is source evidence, not a ZQI implementation or measured gain.

TCQ remains worth evaluating **later**, because limited zeroing does not exhaust
ordinary RDOQ and metric-dependent gains remain unsettled. First improve the
encoder-only baseline: better distortion weighting/reconstructed-neighborhood
checks, ±1 candidates, and correct SplitHuf costs. A trellis over existing ZQI
levels would still be ordinary encoder-only RDOQ. A TCQ-dependent quantizer
lattice would require new decoder semantics/signaling and cannot be credited
with gains obtainable solely by encoder search.

A future ZQI AC-only TCQ design could reset independently per block/channel,
leave nested DC outside state, and maintain independent lane states. RunLevel
must define transitions through every implicit zero and ZRL, with bounded skip
transition tables if useful. SplitHuf would add a serial-within-block quantizer
recurrence to currently independently unpacked magnitudes. Encoder work includes
state/path search and backpointers; decoder work includes states, transitions,
index mapping and any lost sparse shortcut. Those are design implications, not
measured costs or a reason to port AV2's entire syntax.

## Next gate before production adoption

Keep λ=.08 as a provisional comparison, exclude λ=.2 as a general candidate, and
sweep λ=.02/.04/.06/.08/.10 with a dense q5-step grid on broader independently
sourced classes and size buckets. Use actual output reconstruction to protect
text, thin colored edges, texture and smooth regions; preserve per-image,
per-metric overlap and ceilings. Compare 8/32-pixel stripes separately because
fixed restart overhead limits AC savings at low q. Add a separately validated
SplitHuf optimizer before comparing both retained entropy frontiers. Do not
reinterpret E6b's rejected activity-only AQ experiment as this search's result.

Before production adoption, require a broader independently sourced, held-out
matched-quality study across SSIM2, Butteraugli and CVVDP FHD, including protected
text/edges and supported numeric/alpha domains; correct SplitHuf pricing;
bounded memory verification; and native whole-pipeline encode/decode costs.
Later timing work belongs to a follow-up pass. Per user steering, **no native slot is
requested or required before this report**. This study ran no remote timing or
instruction-count proxy ranking. Lab stats add work even when λ=0; eventual
production performance qualification needs a suitable non-instrumented
experimental build, not simply timing these lab binaries. No production adoption
is justified by this first pass.

grid. Build `cargo bench --manifest-path zqi-bench/Cargo.toml --bench matrix
--no-run` under `flock local-scratch/imij-heavy.lock` and
`run-heavy --mem 12G --jobs 6 --`; freeze the printed
executable and hash it **before releasing the build lock**. No native CPU flags.
Use new output directories. For example, with the frozen evaluated executable:

```sh
flock local-scratch/imij-heavy.lock \
  run-heavy --mem 12G --jobs 6 -- \
  local-scratch/zqi-evaluation-20261004/rdoq/matrix-final prepare \

  run-heavy --mem 12G --jobs 6 -- \
  local-scratch/zqi-evaluation-20261004/rdoq/matrix-final score \
  local-scratch/zqi-rdoq-new/prepared/index.json local-scratch/zqi-rdoq-new/scores
```

Generate the original-binary reference spec by retaining only λ=0 profiles and
removing `rdoq_lambda`; the original parser rejects unknown fields. Prepare those
with frozen `matrix-baseline` into `NEW_RUN/baseline`, then run
`python3 benchmarks/analyze_rdoq_2026-10-04.py NEW_RUN`. The analyzer asserts
original-binary/disabled byte identity and saves all rows/overlap anchors.
Raw `provenance.json`, `source-*.json`, `binary-*.sha256`, test/build logs and the
artifact hash inventory identify the tested sources and binaries. Formatting:
`cargo fmt -p zqi -p zqi-gather`; for the separate harness,
